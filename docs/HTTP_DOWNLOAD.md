# 通用 HTTP/HTTPS 下载

在 **下载任务 → HTTP/HTTPS 直链下载** 中输入公开直链，可选指定文件名，点击“添加 HTTP 下载任务”。任务进入现有 aria2 列表，可暂停、继续、移除以及打开下载目录。

## 要求与限制

- 仅在 Electron 启动 aria2 后可用；见 \`/api/downloads/health\`。缺少 \`aria2c.exe\` 时禁用输入。
- 直链不经过夸克、B站 Provider；网页详情页和需要登录、Cookies、动态签名、媒体提取的资源不保证能下载。
- 服务器是否支持 Range 决定是否能够断点续传。设置 \`continue=true\` 并不保证所有来源可续传。
- 新增 \`POST /api/downloads/direct\` 只接收 \`{ "url": "...", "fileName": "optional.ext" }\`；只使用应用当前配置下载目录，不允许单次请求覆盖路径。
- 仅允许 HTTP/HTTPS、无 URL 内嵌账号密码；检查目标域名的首次解析地址和 Windows 文件名，阻止明显的本地/私网地址。首次 DNS 检查无法防止后续解析变化或跳转。**不要把应用本地后端做端口映射或反向代理**。
- 后端现在仅监听 \`127.0.0.1\`，不再对所有来源返回宽松 CORS 头，增加了 Host/Origin 检查。
- 原 \`POST /api/downloads/add\` 保持 Provider 注册的 URL 授权校验，不改动其业务行为。
- 当前已增加 aria2 会话持久化与正常退出保存机制，但仍需要 Windows 实机验证：包括退出、重开、下载继续和文件完整性。

## 暂停/继续和重启恢复测试

- 下载中与排队中可以“暂停”；已暂停的任务可以“继续”。
- Electron 在 userData/aria2/downloads.session 读写 aria2 会话；每 10 秒更新会话与控制文件。
- 正常退出先执行 aria2.saveSession 和 aria2.shutdown；强制终止仅能使用最新自动保存进度。
- 已完成或已移除任务不会加入恢复队列。下载链接若已过期或服务器不支持 Range 仍可能无法续传。
- 测试请**更新到新版本后新建下载任务**，然后按：下载 → 暂停 → 继续 → 正常关闭软件 → 重开 → 核对进度 → 验证文件哈希。

## 统一任务列表（暂停和继续）

- 之前只有上方 aria2 原始任务表可以控制，下面的“任务列表”只有查看详情，因此重启后的“已暂停”任务没有继续按钮。
- 修复后在统一列表中，具有 aria2 GID 的原生任务：已暂停 → “继续下载”；下载中或排队中 → “暂停下载”。
- 操作直接调用现有 /api/downloads/pause/:gid 和 /api/downloads/resume/:gid。源自 Provider 调度引擎的任务不会误用此 aria2 接口。
- 任务卡片的详情按钮与暂停/继续按钮相互独立，不会误开详情弹窗。
- `Ctrl+C` 结束 `npm run dev:desktop` 可能直接终止 Electron 及其子进程，不是可靠的优雅退出路径。请**正常关闭桌面应用窗口**测试优雅退出时的会话持久化，再另外测试 Ctrl+C 异常终止的恢复能力。
- 如果只有 GID、没有文件名，说明 aria2 此时尚未提供文件路径；可以先点击“继续下载”并观察任务详情及上方原始任务列表里的速度/进度。

## 网页链接按后缀批量下载

在“下载任务”区域的“从网页筛选文件下载”中，输入一个公开 HTTP/HTTPS 网页地址与后缀列表，例如 `zip,pdf,mp4`。点击“扫描网页文件链接”，在结果中勾选需要下载的项目，再点击“下载选中”。

- 从页面静态 HTML 的 `<a href>` 与 `<img>/<video>/<audio>/<source src>` 读取静态资源链接，支持相对路径、`<base>`、URL 参数与常见 HTML 实体。仅依据 URL 路径最后一段的**后缀**匹配（忽略大小写）。
- 不执行 JavaScript、不登录、不爬取子页面；脚本动态生成的链接、跳转页、按钮触发的下载无法保证识别。
- 最大 HTML 为 1 MB，最多 4 次 HTTP 跳转、最多展示 200 条匹配项，每批最多手动选择下载 30 条。
- 只扫描公共 HTTP/HTTPS 网页，检查首次 DNS 解析与实际建立连接时的 IP 地址，不允许连接私有/回环地址。每条勾选的 URL 会在加入 aria2 前再次经过已有的 HTTP 直链检查。
- 预览不代表目标链接一定有效；鉴权、签名过期、Range 不支持、文件服务器跳转到非公开地址仍可能失败。
- 不会在扫描完成时自动下载，必须勾选并确认。

## 动态页面：手动交互后扫描（例如 PROSPEROPatches）

打开“从网页筛选文件下载”，输入地址和 `pkg,json` 后缀。先点击“打开交互网页”，在隔离的 Electron 网页窗口里手动点击对应补丁的 **DETAILS / SHARE**，等页面将链接渲染出来；随后回到下载器主窗口，点击“扫描已打开页面”。弹窗中实际渲染的超链接、`data-href`、`data-url`、媒体资源以及尝试打开新窗口/触发下载的 URL 会成为筛选候选项。结果仍需用户勾选才能发送 aria2。

此功能无法保证抓取到仅存在于加密 JavaScript 状态或后台 API 响应中的链接，不会自动展开所有补丁，不会破解验证码或登录，不直接下载网页中被点击的文件。网页浏览器禁用 Node 集成且没有本机 IPC preload；发现链接时自动取消 Chromium 下载以避免绕开 aria2。**若发现的是 PS5 的 JSON 清单/分片 PKG，不代表已经得到完整的单文件更新包。**

## PROSPEROPatches 弹窗的正确扫描方式

- 当提示“静态 HTML 扫描：找到 0 条”，代表点击的是绿色静态扫描按钮。该站依赖 JavaScript 加载更新列表，静态 HTML 不包含详情弹窗数据。
- 点击“打开交互网页” → 手动进入对应版本详情 → 如有 JSON、SC 或 Download 链接，点击相应链接让页面尝试导航/下载 → 返回主界面点击“扫描已打开页面（交互）”。
- 交互扫描会查看浏览器已渲染的链接、部分数据属性与可见文本 URL，也会**被动记录**该隔离会话中实际发起的常见文件请求（.pkg/.json/.xml 等）；它不自动下载。单纯点击只显示版本、日期、大小的 Details 可能不产生真实文件链接。
- 找到 0 个时显示 DOM 候选数与网络请求候选数，便于定位是否已真正触发文件链接。
- 对 PlayStation 的大型更新而言，单个 `/app/pkg/` 可能只是一个分片。请优先识别 JSON manifest 或 `_sc.pkg`，目前下载器不会根据 JSON 自动合并为完整 PKG。

## 自动发现后缀并按类型筛选（新版默认）

- **后缀输入框可以留空**：静态 HTML 扫描与交互式网页扫描默认先发现候选文件，再按实际后缀生成类型复选框，例如 `.pkg (32)`、`.json (4)`、`其他/未知 (1)`。
- 类型复选框**仅过滤显示**，不会自动选择文件或开始下载。扫描完成时默认显示所有类型，但默认没有任何文件勾选。
- 文件列表里的复选框负责决定下载哪些文件。“选择当前筛选”受每批最多 30 条的上限约束。“清空已选”清空所有类型的下载选择。
- 取消显示一种后缀时，此前勾选的文件**不会被清除**；界面明确显示“隐藏已选”数量。这样切换过滤器不会丢失之前的人工选择。
- 原“高级：扫描前限制后缀”仍可输入 `pkg,json` 进行预过滤，兼容老工作流。默认留空为自动发现。
- 自动分类基于 URL 路径或某些查询参数中的文件名，不读取文件 MIME、不嗅探文件内容；无后缀但明显为下载端点的链接显示为“其他/未知”。
- 普通网页导航、JS/CSS/HTML 资源默认不作为下载候选；动态网页若没暴露链接仍需使用交互式扫描。
- 每个文件仍必须手动选择后才能通过原来的 `/api/downloads/direct` 加入 aria2；后端 HTTP/HTTPS 校验、私网地址拒绝与下载目录限制不变。
